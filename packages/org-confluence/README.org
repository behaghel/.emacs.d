* Org Confluence

=org-confluence= is a package-style Org integration for Confluence.  It owns
Org ↔ Confluence Storage Format conversion, page import/publish/sync,
Confluence people resolution, inline comment marker preservation/repair, sync
status reporting, and Confluence-backed =org-comments= operations.

This directory is intentionally shaped as a package boundary inside the Emacs
configuration.  The package should remain extractable: reusable behavior lives
under =packages/org-confluence/=, while site defaults, personal leader keys,
Evil/Bépo bindings, and window/layout policy live in consumer configuration.
In this repository, personal activation lives in:

#+begin_example
modules/interactive/org/confluence.el
#+end_example

* Canonical entry points

The canonical package entrypoint is:

#+begin_src emacs-lisp
(require 'org-confluence)
#+end_src

=org-confluence.el= loads the export backend, command facade, comments backend
integration, people-store support, and mode-level source markers.  Users should
activate buffer-local integration with either:

- =org-confluence-mode= for an already linked Org buffer; or
- =org-confluence-mode-maybe= from =org-mode-hook= to enable only when
  Confluence metadata such as =#+CONFLUENCE_PAGE_ID= is present.

Former short wrapper files such as =api.el=, =commands.el=, and =export.el= are
not part of the package boundary.  Code should require the canonical
=org-confluence-*= modules directly.

* Installation

When used from this repository, no separate installation is required.

For a separate consumer of this source checkout, make the dependencies available
first: Emacs 29.1+, Org 9.6+, org-comments 0.1.0+, and ox-sync 0.1.0+.  The latter
packages also require Context Panels and Magit Section's dependency closure.
No separate org-confluence repository or package archive submission is assumed.

#+begin_src emacs-lisp
(dolist (directory '("packages/org-comments" "packages/ox-sync"
                     "packages/org-confluence"))
  (add-to-list 'load-path (expand-file-name directory "/path/to/checkout/")))
(require 'org-confluence)
(add-hook 'org-mode-hook #'org-confluence-mode-maybe)
(setq org-confluence-api-base-url "https://example.atlassian.net"
      org-confluence-api-default-space "~personal")
#+end_src

Local Storage XHTML conversion needs neither cfl nor credentials.  Import also
requires an Emacs build with native libxml2 support; an unsupported build gets
an actionable user error before conversion.

Live CLI-backed page/attachment operations require the external =cfl= executable
selected by =org-confluence-api-cfl-command=.  Cloud REST paths read the config
selected by =org-confluence-api-cfl-config-file= (default
=~/.config/cfl/config.yml=).  The existing scalar reader recognizes base URL,
email, API-token, and optional cloud-ID fields; it is not a general YAML parser.
Keep credential files outside this checkout and never put tokens in Org source.
The offline check below does not validate live CLI compatibility or authentication.

=org-confluence-mode= registers the Confluence =org-comments= backend and, when
=org-confluence-enable-org-comments-mode= is non-nil, enables
=org-comments-mode= for local comment commands and overlays.  The package mode
does not install personal leader keys, Evil bindings, or layout policy.

The mode binds one package-native dispatch command by default:

#+begin_example
C-c C-x C  org-confluence-dispatch
#+end_example

Set =org-confluence-keymap-prefix= to nil before enabling the mode to leave the
mode map without a default binding, or set it to another key sequence and call
=org-confluence-rebuild-mode-map=.

* Workflows

** Export and publish

- =org-confluence-export-as-xhtml= opens a temporary Storage XHTML preview;
  the native Org export shortcut is =C-c C-e C X=.
- =org-confluence-export-to-xhtml= writes Confluence Storage XHTML for the
  current Org buffer or subtree.
- =org-confluence-publish= updates an existing Confluence page identified by
  buffer or subtree metadata.
- =org-confluence-publish-dwim= updates an existing page or creates a page when
  enough space/parent metadata is available.
- =org-confluence-publish-force= bypasses stale remote-version and
  inline-comment preservation checks after confirmation.

When an Org buffer records =#+CONFLUENCE_PAGE_VERSION=, publish checks the
current remote page version before uploading assets or editing the page.  If the
remote page changed since the last recorded sync, normal publish refuses and asks
you to run =org-confluence-sync-page-current= or explicitly force publish.

Publishing uploads local image assets before page update.  When
=org-confluence-publish-preserve-inline-comments= is non-nil, publishing fetches
existing page storage and inline comment metadata so active inline comment
markers can be reinserted into newly exported storage XHTML when safe.

** Import and pull

- =org-confluence-pull= refreshes the current Org file from Confluence storage;
  call it with a prefix argument (=C-u M-x org-confluence-pull=) to include
  comments.
- =org-confluence-pull-to-file= accepts =:include-comments t= to pull page
  comments into the adjacent =.comments.org= sidecar while keeping the main Org
  page free of comment content.
- =org-confluence-pull-child-page= selects a descendant page/folder and pulls it
  beside the current Org file.

Import converts common Confluence constructs into readable Org, including
status macros, panel/callout macros, emojis, tables, lists, dates, inline
comment markers, and user mentions.  Org date timestamps export as Confluence
native =<time datetime="YYYY-MM-DD" />= elements; imported Confluence time
elements become inactive Org dates such as =[2026-07-02]=.

** Page and comment sync

- =org-confluence-sync-page-current= syncs page content only.
- =org-confluence-comments-import= imports footer and inline comments into the
  =org-comments= sidecar.
- =org-confluence-comments-push-current= pushes the current local sidecar
  comment to Confluence.
- =org-confluence-sync-current= performs page sync and then comments sync when
  the page sync is safe.

The =org-comments= backend operation =:sync= is intentionally comments-only.
Full page synchronization remains in =org-confluence-sync.el= and is exposed via
=org-confluence-sync-current=.

** Sync status

=org-confluence-sync-status= opens a read-only report for page, attachment,
people, and comment state.  =org-confluence-mode= can show a compact
source-buffer marker whose activation opens this report.  The report separates
content operations (=y= sync page, =f= fetch/pull page, =p= publish, =!= force
publish) from comment operations (=Y= sync page+comments, =F= fetch page+comments,
=i= import comments, =C= open sidecar, =L= list remote comments).  Optional UI
callback variables let personal configuration reuse surrounding windows without
making the package depend on personal context-panel modules.

* Offline standalone workflow

From this checkout's root:

#+begin_src sh
devenv -q shell -- ./scripts/org-confluence-standalone
devenv -q shell -- ./scripts/org-confluence-standalone --interactive
#+end_src

The batch check copies source, package-local tests, examples, org-comments,
ox-sync, Context Panels, and the Magit Section dependency closure to a disposable
sandbox.  It uses =emacs -Q= with a temporary HOME, no personal helpers or
configuration modules, and warnings-as-errors compilation.  Emacs network
connections and external =process-file= commands are blocked.  No dependencies
are downloaded; use =STRAIGHT_BUILD_PATH= and =CONTEXT_PANELS_PATH= for existing
source dependency locations when needed.

The interactive [[file:examples/standalone.org][walkthrough]] activates local Confluence/Org-comments integration:
- =org-confluence-demo-preview= exports into the normal Storage XHTML buffer.
- =org-confluence-demo-roundtrip= imports that preview into a separate read-only
  Org buffer.  Re-export after source edits before importing the preview again.
- =org-confluence-demo-check-cli= reports the missing-cfl diagnostic without
  starting a process, dumping PATH, or moving to another buffer or position.

Inspect the fixture's headings, bold text, callout title/type, date, lists, and
verbatim code.  Conversion does not rewrite the source.  HTML spacing is
normalized; the sample does not claim byte-for-byte Org fidelity, attachment
transfer, or support for every Confluence construct.

The demo disables Babel evaluation, credential reads, HTTP transport, CLI
execution, and browser opening in its isolated Emacs.  =C-c C-e C X= is local
preview; =C-c C-e C C= and =C-c C-e C O= are publishing commands, not previews.
Remote actions remain disabled even if a real cfl happens to be on PATH.
The existing Confluence status report is retained, not migrated to ox-sync.
Exit the sample Emacs to remove its temporary source and previews.

* Development

Generate this reference from defcustoms/commands with:

#+begin_src shell
scripts/elisp-package-docs \
  --load packages/org-confluence/org-confluence.el \
  --prefix org-confluence- \
  --command-prefix org-confluence- \
  --out packages/org-confluence/docs/generated
#+end_src

All conversion, API, people-store, and facade tests live under =test/= inside
this package.  They require a dedicated batch process: fixture support relocates
HOME and runtime caches, and rejects unmocked credential reads, network access,
and external processes even when best-effort code catches ordinary errors.
Explicit temporary config/transport fixtures remain available.  Do not load the
test support into a personal interactive Emacs; it refuses that environment.
The repository runner selects the tests together from package changes:

#+begin_src shell
devenv -q shell -- ./scripts/elisp-ert packages/org-confluence/org-confluence.el
#+end_src

Use =org-confluence-standalone= above for the source-only clean-room check;
its transport mocks and process guards do not claim live-service verification.

Before handoff, also run package byte-compile/lint, =load-check=, and the docs
generation command above.
